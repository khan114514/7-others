# Exact Multihead Retrieval Kernel

## Goal
Implement a CPU tensor algorithm that computes the operator below and minimizes inference latency. Inputs are float32 features, three per-head linear maps and two scalar controls. A valid submission is a pure `attention` function in `/workspace/solution/method.py` that satisfies the numerical contract for unseen inputs.

## Task Setting
The environment contains Python 3.12, PyTorch 2.5.1 and NumPy 2.2.6. No training, downloaded weights or external data are required. A direct correct Starter is available read-only at `/workspace/environment/starter/method.py`; the writable initial solution copies this Starter. Public generated inputs and the public scoring program are available under `/workspace/environment/`. Final verification uses separately generated private inputs in an independent environment after the final solution is transferred.

## Objective and Metrics
Let `x` have shape `(B,L,C)` and each map `wq,wk,wv` have shape `(H,D,C)`. For each head define `q=x wq^T`, `k=x wk^T`, `A=q k^T / sqrt(D)`, `P0=softmax(A)` and `P1=softmax(((1+alpha)/2) A + ((1-alpha)/2) A^T)` along the last axis. Define `u0=P0 x`, `u1=P1 x`, `m=u0+beta*(u1-u0)` and `r=clamp(max(||u1||_2,1e-6)/max(||m||_2,1e-6),0.25,4.0)` per head and token. Return the concatenated head outputs `(r*m) wv^T` in shape `(B,L,H*D)`. There are no linear biases or final output map in this operator.

Every output must be finite float32 CPU with the specified shape and satisfy elementwise `abs(actual-expected) <= 3e-5 + 3e-4*abs(expected)`. Inputs must not be modified. Tensor computation is permitted; changing the operator is prohibited. PyTorch runs with one intra-op and inter-op thread. For each case, the candidate and the protected healthy Starter control are independently measured using process CPU execution time in milliseconds (`time.process_time_ns`): median of 11 measured calls after 3 warmups per case, arithmetic mean across cases, then arithmetic mean across seeds `[17,29,43,71,101]`. The raw metric is the arithmetic mean of per-case candidate/control CPU-time ratios, then the arithmetic mean across seeds. The control is freshly measured in the same evaluation with identical inputs and budgets, so each result compares methods under the same hardware conditions, rather than using a millisecond anchor measured on another machine. Lower is better. Timing is stochastic; a claimed improvement must exceed three times the Baseline sample standard deviation across the five complete paired seed runs. Case generation is deterministic per seed. Wall-clock latency is reported separately as a diagnostic; scheduling and CPU quota delays are excluded from the primary CPU time metric.

The continuous score is `(B_latency - measured_latency)/(B_latency - U_latency)`, without clipping. `U_latency=0` is the mathematical ratio floor, not a Reference result. The calibrated split-specific Baseline anchor is stored in the protected protocol. The calibrated ratio anchor comes from all five complete formal Baseline runs. The public five-seed Baseline ratio anchor is 1.06765098401. Private evaluation uses its own protected split-specific Baseline ratio anchor. Numerical errors and constraint violations produce invalid score `-1`; malformed submissions, timeouts, resource failures and infrastructure failures are separate diagnostic states and do not masquerade as zero performance.

## Allowed Scope
Only `/workspace/solution/method.py` may be modified. Implement `attention(x,wq,wk,wv,alpha,beta)` returning a tensor. Helpers and arbitrary algebraic rearrangements using CPU PyTorch and math are allowed. Decorators are limited to PyTorch no_grad/inference_mode contexts; custom persistent-state decorators and mutable defaults are forbidden. Read the Starter, public protocol and public evaluator. Run `/workspace/solution/solve.sh` for Dev evaluation and read `/workspace/public-results/result.json`. Final verification recomputes outputs and timings; candidate-reported scores are not accepted.

## Hard Boundaries
The method file must be a regular file of at most 256 KiB. Imports are limited to `torch` and `math`. Filesystem access, process creation, introspection, dynamic execution, runtime/thread reconfiguration, mutable module/function state, persistent result caching, external communication and input mutation are forbidden. The source guard and protected worker implement the restrictions; Docker limits each environment to one CPU and 2 GiB memory. Networking is disabled during verification; the Coding Agent phase permits only the two configured model inference hosts for its CLI. Research web search and network tools are prohibited; local shell tools may inspect public files and invoke Dev evaluation only. Each benchmark case has a 120-second timeout and the complete evaluation has a 1800-second limit. Protected programs and data cannot be modified. Never access final private evaluation assets or another model's results.

## Submission Instructions
Keep `/workspace/solution/method.py` and the frozen `/workspace/solution/solve.sh`. The function takes six positional arguments; scalar controls are Python floats. There is no submission JSON or model checkpoint. Harbor transfers `/workspace/solution` to its original path in the independent Verifier, which validates source and directly executes the candidate. Additional files and self-reported scores are ignored.

## Workflow & Iteration
This is an anytime task. Implement a method, run the protected public evaluator, inspect correctness and measured latency, and retain or revert using those results. Whenever a better valid method is found, replace `method.py` with that current best; the most recent valid submission is scored. Typical Dev evaluation is intended to finish in minutes and must stay within the complete evaluation budget. Preserve the current best before experimenting, then restore it before completion.

## Completion Criteria
The final method respects the fixed operator, passes the source guard and all numerical gates, produces a finite measured score with the calibrated protocol, and reruns from a clean snapshot. Protected files remain unchanged and final private inputs have not been accessed during optimization.
