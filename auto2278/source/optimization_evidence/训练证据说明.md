# 成对运行与优化面证据

本题不涉及训练或微调，不交空 model/ 目录；所有 result.json 的模型产物项均为 NOT_APPLICABLE。任务来自公开注意力检索方法，但只评测固定算子的精确 CPU 实现，不将核级 CPU 加速表述为整图 GPU 吞吐提升。

正式协议为 attention-exact-cpu-v2，seed 在运行前固定为 [17,29,43,71,101]。Baseline 与 Reference 对每个 seed 使用相同输入、权重、PyTorch 2.5.1、float32、单线程、1 CPU、2 GiB、3 次 warmup 与 11 次计时。原始指标是逐 case 的候选进程 CPU 时间除以同次独立测量的健康 Starter 时间，再按 case 和 seed 做算术平均；墙钟时间单列诊断。Baseline 与 Reference 的执行顺序逐 seed 交替。不得挑较差 Baseline 或只交最好 Reference。

正式 Baseline 是未修改 Starter 的正确直接实现。Reference 在合法函数接口内更改计算顺序，在部分形状上用 token Gram 矩阵精确求投影前的范数，再计算投影后的输出；这不是改变 alpha/beta 参数，不改变数值语义。完整公式、精度门和接口见题面。CPU 时间比避免硬件型号或主频不同造成固定毫秒锚点失效。这里没有训练数据、预训练模型或 checkpoint 的选择差异。

U=0 是在任何实验之前固定的非负相对时间下界。B/R 使用全部五个正式 seed 的均值。归一化 score=(B-x)/(B-0)，连续、不裁剪；Baseline 均值对应 0。随机性来自计时而非训练，必须用 n-1 的 Baseline 样本标准差复算至少 3σ 改善，以及 Reference 归一化 [0.15,0.8]。所有结果与统计以 comparison_summary.json 为准；校准尚在运行，不能预写通过结论。

每轮 result.json 对应真实执行，run.log 保留原始 stdout/stderr。缺失信息不得从文件时间猜测。额外的第一版绝对 CPU 时间实验保留在 expert_evidence/absolute_cpu_time_protocol_v1/，其原始数值不会混入第二版正式均值或模型轨迹。
