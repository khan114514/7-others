# Original method evidence: source-bound audit

This report audits the same native Bifrost session. It reads saved graph/result data and published source only; it does not execute the builder, run Dev, or use a GPU. The 48-window source is evidence of linked own method edits and feedback, not a declaration of effectiveness or research-time credit.

## Cross-check of the 48 feedback windows

The supplied source `expert_evidence/original-source-method-loops/gpt-actual-method-feedback-windows.json` contains 48 windows and 48 distinct current artifact hashes. Each listed current artifact differs from its listed prior artifact. I independently matched windows 10–47 to saved `experiments/<name>/dev-result.json` files: all 38 current artifact digests equal the worker result artifact digest, and all 38 original result digests equal the raw saved result-file SHA256. The preceding artifacts also resolve to saved Dev results. Windows 4–9 match the recovered `own-previous-Dev-evidence.json` artifact/result digests and recovered builder/program receipts, but their raw result JSON is absent. Windows 0–3 have source-window hashes and pass flags but no matching local builder/result payload in the restored tree, so I leave their method and score unclassified.

The source-window `original_binding_SHA256` values are preserved in the JSON report. The raw binding objects are not restored, and the worker result field `source_binding_sha256` is a different named value; I do not equate those hashes. The original native archive itself is not present for re-reading call payloads, so the listed record indices are retained as source citations, not independently reconstructed transcript content.

Representative direct cross-checks include window 10 (`32_text_output_rows` → `33_text_query_attention`), window 18 (`51_compiled_image_mlp` → the quality-invalid `52_compiled_image_rms`), window 19 (`52` → valid `53_compiled_image_rotary`), window 44 (`96_compiled_prefix_text_qkv` → `97_compiled_frequency_prefix`), and window 47 (`100_compiled_value_columns_producer` → `101_compiled_column_projection_residual`). For these, source-window artifact/result hashes, experiment feedback, builder/program and the corresponding research-note entry agree. Full per-window record indices and hashes are in the JSON companion.

## Current selected graph: compile boundaries and liveness

The read-only selected `method.py` / `program.json` match the saved 115 builder/program byte for byte in the restored workspace. The version-2 graph has 107 nodes and output `output`; its canonical digest is `845b8cbe96e3221b7615294d09a320b6d87223c3502886f1ea502b04fa20be5e`. The evaluator applies the body through all 28 decoder layers, then performs the image-tail RMS normalization and vision head linear projection (`full_decoder_evaluator.py`, `decode`).

| Region (node positions) | Lifetime / nodes | Runtime inputs from outside region | Values returned across boundary |
|---|---|---|---|
| `frequency_prefix_compiled` (21–52) | prefix, 32 nodes | `cos, sin` | `cos_axis_0, cos_axis_shape_0, cos_axis_1, cos_axis_shape_1, cos_axis_2, cos_axis_shape_2, cos_section_0, cos_section_1, cos_section_2, cos_section_3, cos_section_4, cos_section_5, cos_layout, sin_axis_0, sin_axis_shape_0, sin_axis_1, sin_axis_shape_1, sin_axis_2, sin_axis_shape_2, sin_section_0, sin_section_1, sin_section_2, sin_section_3, sin_section_4, sin_section_5, sin_layout, image_cos, image_sin, image_sin_first, image_sin_negative, image_sin_second, image_signed_sin` |
| `image_pre_softmax_compiled` (65–83) | stage, 19 nodes | `image_input_norm, vision_qkv_weight, vision_qkv_bias, image_cos, image_signed_sin, text_key_rotary, image_attention_mask` | `image_v, image_masked` |
| `image_post_softmax_output_compiled` (85–97) | stage, 13 nodes | `image_prob_fp32, text_v_rows, image_v, w:self_attn.vision_branch_o_proj.weight, image_input_rows` | `image_residual_rows` |
| `image_mlp_compiled` (103–103) | stage, 1 nodes | `image_post_norm, w:vision_branch_mlp.gate_proj.weight, w:vision_branch_mlp.up_proj.weight, w:vision_branch_mlp.down_proj.weight` | `image_mlp` |

The `image_pre_softmax_compiled` body computes the image Q/K/V projection, Q/K rotary composition, text/image key composition, seven-way KV head repeat, score contraction, scale and mask addition. Its outputs `image_v` and `image_masked` feed two downstream consumers. Node 84’s FP32 softmax is outside every region. The next compiled region accepts that FP32 probability tensor, performs the original BF16 cast and value packing/repetition/reversed contraction, canonical output reshapes, O projection and image residual; only `image_residual_rows` crosses that boundary. `image_post_norm` remains eager before the atomic compiled `image_mlp`, whose result is combined by the eager residual/output tail.

The frequency region has 32 prefix-lifetime nodes. Because the published V2 validator returns every member of a prefix region, every one is individually cached/counts toward the prefix budget. The whole selected graph has 67 prefix nodes and the saved allocation-free validation sums their declared storage to 3,871,096,320 bytes over 28 layers, below the 7,516,192,768-byte cache limit. The text branch and fixed mask/frequency nodes are reused per layer within a prompt rollout; the changing image branch is stage lifetime. `TensorDAG` builds use counts, removes data-only values after their last graph use, and stores prefix results separately; prompt/repetition reset clears these numerical cache entries. Compilation reuses a fixed Inductor executable, not those tensor values. Warmup compilation and first execution are recorded separately, then prefix values are reset before timed reconstruction.

This is graph-level liveness, not physical allocation proof. The compiler returns `image_v` as an observable region value and source does not report whether its produced view keeps a larger QKV backing allocation alive. Nor does the worker report generated kernels, strides, or an allocation attribution per region. The 115 peak is measured for the complete decode and cannot identify which region caused it.

## Eager profiling is historical, not a profile of 115

`own-public-stage-profile`, `own-public-operator-profile` and `own-public-kernel-profile` all bind to experiment 41 (the older eager graph), not to compiled experiment 115. The stage profile has 96 timings over three disclosed 32-step cases: mean first-stage latency 125.56 ms and mean later-stage median 58.30 ms, consistent with included prefix construction but not attributing time to a particular current region. The operator/kernel traces instrument only one case’s first and next forward; the instrumentation may perturb time, and inclusive ranges do not sum to decoder wall time. They cannot identify 115’s kernel schedule.

The actual follow-up experiment 49 split the image MLP by CFG batch. It passed disclosed numerical checks but measured candidate mean 2,503.36 ms, reward 0.647971, and did not reduce peak allocation; it was worse than the then-selected experiment 41. That rejects the tested split under that eager graph, not all future compiled MLP partitions. It also illustrates why the older eager annotation ranking is not a causal explanation of compiled 115.

## Stopping judgment and bounded future questions

I preserve `research-exhausted.json` as an interim bounded judgment: no universal exhaustion or global optimum is established, no formal QA/PASS is claimed, current 115 has no generated-kernel profile, cross-candidate paired gain is not established, and the withheld six-prompt 256-stage three-repeat evaluation remains untested. The original round-14 export gap also remains recorded. This retrospective source audit does not change those limits or add a Dev score.

Two concrete source-supported questions remain, conditional on a future trusted diagnostic environment: (1) measure the actual stride/storage alias and live-allocation effect of returning `image_v` from the pre-softmax region, while keeping the exact graph and precision fixed; (2) test whether a new data-only frequency graph can retain only the final reusable layouts without caching all helper nodes, while measuring the repeated helper work and preserving the prompt-reset and 7-GiB rules. These are unresolved questions, not claimed improvements. The fixed catalog’s every-prefix-node cache accounting, compile-region homogeneity and no-fallback rules remain constraints. No experiment was run for this report.
