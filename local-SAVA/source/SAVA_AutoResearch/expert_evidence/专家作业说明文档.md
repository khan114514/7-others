# SAVA 专家作业说明

双模型研究轨迹、唯一全局 best_method 的干净复跑和最终运行配置十二小时稳定性已实际完成。本文随完整候选包进入独立发布自检，尚不声明发布完成；两份独立报告及共识另行绑定封定 ZIP 的同一 SHA256，不能用作者预检代替。

## 题目及来源

Task ID：`autoresearch/hierarchical-transport-valuation`；题型 S1；变体 `hierarchical-valuation-cpu-v1`。研究方向为分层最优传输估值的数值算子优化。论文、固定官方 commit、真实小规模复现、共同修复和与论文的范围差异见 [方法与复现说明](方法与复现说明.md) 与 [来源对齐说明](来源对齐说明.md)。实际证据支持中等难度。动态有效性审核材料在题包外独立管理，不向研究 Agent 提供。

## 输入、输出与优化面

输入是固定图像 encoder 的10维 logits、候选观测标签、干净公共参照 logits/标签和 seed。输出为每个候选点的一维浮点估值。仅 method.py 可修改，接口为 `value(x, y, r, ry, seed)`；solve.sh、公开/私有资产、质量门、资源和评分器固定。可研究 batch 构造、经验标签几何、双势与 coupling 求解、校准和聚合；提交不能读写文件、访问解释器内部、使用网络或自报分数。

正式任务完全没有训练或微调，不交付训练 checkpoint。冻结 encoder 的来源存在已披露的不确定性，它不能充当已验证训练充分性的证据。本题评测相同固定表示上的数值保真与计算时间。共同修复不作为 Reference 创新。

## 构建与运行

以下路径均相对于题包的外层目录。Actor build context 只用 environment/，不得把整个题包或 Reference 复制进 Actor。

```sh
docker build -t sava-actor:v1 workspace/harbor_task/environment
docker build -t sava-verifier:v1 workspace/harbor_task/tests
```

完整 Public/Dev 可以在标准镜像中运行。宿主只启用本题容器，不使用 GPU；应避开自己其他数值作业以减小计时干扰。

```sh
docker run -d --init --name sava-public-check --network none --cpus 2 --memory 2g --cap-drop ALL --cap-add SETUID --cap-add SETGID --cap-add KILL sava-actor:v1
docker exec --user 1000 --workdir /workspace/solution sava-public-check sh ./solve.sh
docker rm -f sava-public-check
```

预期输出为包含 status、raw_metric、score、quality_valid、method_sha256 和 protected result_path 的 JSON。必须实际完成30例、每例九次新进程；输入和依赖加载不计入方法时间，全部方法计算及输出传输计入。由于计时噪声，不要求输出等于历史某个秒数。启动入口已在标准镜像上实测，无需作者专用模型 adapter 才能启动 Dev 服务。

专家侧 Reference 在 `workspace/reference/method.py`。独立专家测试可将它复制到临时评测容器的 /tmp 后，以 root 调用该镜像内的 evaluator，对同一公开 cases/targets/protocol/worker 执行九次评测。其路径不进入研究模型 Actor。正式 Reference 的五个 seed 运行已完成，不应为制作新分数盲目覆盖原记录。具体测量配置、命令、输出和源码哈希均在 optimization_evidence/。

Harbor0.24.0 已真实加载 schema1.4。task.toml 明确 `environment_mode="separate"`，两个环境分别为2CPU、2048MiB、无GPU。当前 Native NOP 的同 Trial config、result、reward、日志、移交 method.py/solve.sh 和 task checksum 位于 `harbor_nop/current/`。这是作者本地接口测试，不是平台运行或独立 QA 重跑。平台可按自己的调度环境重新构建并运行。

## 评分设计与正式成对证据

原指标为各例九个独立进程的方法 elapsed time 中位数，各 seed 六例均值，再取五 seed 均值，方向为越小越好。公开 B=0.5214946210980997秒，R=0.38039968356703563秒，U=0。归一化为 `(B-x)/(B-U)`，不截断分数；零时间仅为非负时间的数学下确界。

每次输出须同时满足 normalized RMSE≤0.01、Spearman≥0.999、top-quarter overlap≥0.98。Dev seeds 101/202/303/404/505 的正式 B/R 共540次调用均有效。R 相对提速27.0558759%，提升为23.1196505个 Baseline 样本标准差。完整 paired 数据、原日志和摘要位于 `optimization_evidence/comparison_summary.json` 及各角色/seed 子目录。这些是非训练随机计时记录，不伪装成重复训练。

Hidden 的规模不同，独立 Baseline 锚点为0.9686492823001269秒。隐藏校准仅执行共同 canonical，没有 Reference 或候选选优反馈。最终候选按公开受保护评分选优；本地 NOP 的 Hidden reward 不作为算法收益结论。

## 隔离、移交与版本

Actor 只看到公开题面、公共输入、共同 starter 和受保护 Dev 客户端。method.py 可写，solve.sh 固定；Reference、专家材料、Hidden cases/targets 不可见。可信主控保存模型凭据；Actor 只有任务范围的模型桥接能力，没有长期密钥。Seed 的全部真实请求使用 Coding Plan 指定路径，未采用付费路径或替换模型。

Hidden 资产仅在 tests/ 独立 verifier build context，权限限制和候选降权执行由相应 Dockerfile/worker 处理。移交的是源码，verifier 重新执行并计算指标，不能通过编辑历史结果得分。不要给 Actor 挂载宿主题包、Docker socket 或作者工作目录。

当前仍使用 guard-v5 镜像，运行配置另补根服务 CAP_KILL 以执行既有超时清理；NOP008 已是历史，新 NOP009 真实完成、零异常并核对当前全部147个任务文件checksum。标准启动、已声明的间接 I/O 禁令和两文件资产边界修复见 `runtime_repairs/current_binding.json`。除 guard 外 evaluator 全部 AST 节点相同，数值函数、worker、inputs/targets、seeds、质量门和锚点不改。旧模型 Actor 与旧 runtime_view 记录各自历史版本，不能冒充当前镜像观察。当前 guard 已接受66份此前真实测量源码；最终候选仍须重新核验并干净复跑。

## 已知限制

本题不是论文全部 benchmark 的复现，也不是最好噪声检测器。冻结权重训练来源未知，缓存路径与官方小样例只证明高度排序一致；canonical 的 practical 各层正则约定并非统一熵参数的严格理论等价。时延受并发和宿主调度影响，单次最高分与干净复跑可有差异，正式 B/R 必须看完整配对记录。

已知负向 guard 回归和 UID/资源/私有路径实测不等于穷尽操作系统攻击面。最终运行配置实际持续观察 43815.052294 秒，六次30-case单重复功能检查均通过；最后真实 Actor IPC 完成30-case/270次质量记录，客户端退出码0、quality_valid=true，当前147任务文件一致，无OOM、重启或服务失活，证据见 stability/current/。该稳定性末次使用 canonical Starter，不作方法优选；其 raw_metric=0.613619669633、score=-0.176655798176 反映一次随机时延，不能冒充零分或最佳方法复跑。此前观察不累加，本观察不计研究时长。两份相同 SHA256 的全新独立 release-self-check 和无未解决分歧共识仍待完成，报告在封定 ZIP 外单独交付。全部交付仅本地制作，不宣称已上传、被平台接受或正式 Hidden 审核通过。

运行配置超时修复的真实回归为 TIMEOUT/60秒、Actor UID1000/CapEff=0、无遗留候选 worker，见 runtime_repairs/timeout_enforcement。旧稳定性观察保留但不计新配置12小时达标。
